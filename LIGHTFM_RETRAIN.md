# 🧠 RecoSense: Heavy Hybrid Retrain (Level 2)
**Type:** Python Deep Learning / Context-Aware Hybrid Filtering  
**Algorithm:** LightFM + ABSA (RoBERTa)  
**Execution Time:** ~30–60 seconds

## 📝 Overview
The **Heavy Retrain** is the "A.I. Brain" of RecoSense. It moves beyond simple popularity by merging two powerful AI methodologies: **Collaborative Filtering** (User Behavior) and **Content-Based Filtering** (Product DNA).

By using **ABSA (Aspect-Based Sentiment Analysis)** scores generated by RoBERTa, the engine doesn't just know *that* you liked a phone; it understands *which features* of the phone (Battery, Camera, Display) attracted you.

---

## 🚀 The Hybrid Pipeline

### 1. The ABSA "DNA" Injection 🧬
Before training begins, the engine loads the `absa_reviews.json` dataset.
- **Feature Extraction:** It identifies all sentiment-aware aspect scores (e.g., `battery_score`, `camera_score`, `performance_score`).
- **Item Feature Matrix:** It creates a stable "DNA" profile for every product based on thousands of historical reviews processed by the **RoBERTa model**.
- **The Role of RoBERTa:** RoBERTa acts as the offline "Feature Engineer," defining the ground-truth characteristics of the hardware.

### 2. Matrix Factorization (The Learning) 🔗
Machine learning doesn't understand text; it understands high-dimensional grids.
- **User-Item Matrix:** Maps "Who liked what" (Interactions).
- **Item-Feature Matrix:** Maps "What makes this phone good" (ABSA Vectors).
- **Training (WARP Loss):** The model adjusts internal **User Taste Vectors** to minimize the distance between a user and products that have the features they seem to prefer.

### 3. The Vector Interaction Logic
How the system evolves after a user interaction:

| Action | Impact on ABSA Vector | Impact on User Vector |
| :--- | :--- | :--- |
| **User "Likes" a phone** | ❌ No change (Phone hardware is static). | ✅ **Updates.** AI learns the user gravitates toward the ABSA features of that phone. |
| **New 5-Star Review** | ✅ **Updates.** Product features (e.g., `camera_score`) shift during the next training cycle. | ✅ **Updates.** Strengthes the bond between the user and those specific aspects. |

## 🛠️ Step-by-Step Lifecycle

### phase 1: The Hand-off
- **Trigger:** Admin Panel click or high interaction threshold.
- **Status Lock:** MongoDB is set to `status: "running"` to prevent race conditions.
- **Process Spawn:** Node.js triggers the Python `.venv` environment to run `train_lightfm.py`.

### Phase 2: Training Cycle
1. **Data Load:** Merges historical reviews + Live MongoDB Likes.
2. **Indexing:** Maps IDs to numerical indices for Sparse Matrix efficiency.
3. **Training:** Runs for **20–30 Epochs** using **WARP (Weighted Approximate-Rank Pairwise)** loss.
4. **Optimization:** Specifically designed to ensure the *best* items appear at position #1, rather than just predicting a simple rating.

### Phase 3: Pre-computation & Sync
- **Massive Batch Prediction:** The model calculates a unique Top-20 list for **every single user account** in the system.
- **JSON Hand-off:** Results are saved to `lightfm_recs.json`.
- **Database Ingestion:** Node.js performs a bulk `findOneAndUpdate` in MongoDB to make the recommendations live.

## 🧠 Key Philosophies

### Hybrid vs. Pure Collaborative
Pure Collaborative models suffer from "Cold Start" (new items can't be recommended). By using **ABSA Features**, our hybrid model can recommend a brand-new phone simply because its "Battery Score" is similar to phones you liked in the past.

### Semantic Awareness
Because we use **RoBERTa**, our "Feature Matrix" is based on actual human sentiment, not just manufacturer spec sheets. If reviews say the "Battery is disappointing," the model learns that as a negative feature, regardless of the mAh listed on the box.
